# 渲染与运动流畅度

## 实现

- 240 Hz 物理循环不渲染图像，只提交不可变场景快照。
- 两个独立 DIRECT 进程并行渲染外部和腕部相机；最多一对帧在途。
  渲染较慢时跳过采样，不让旧任务积压。
- 图像、CameraInfo、相机 TF 保留快照时间，支持按时间戳匹配原始关节状态。
- PyBullet 内置调试图像预览关闭，避免在 GUI 中反复刷新相机缓冲区。
- 控制指令为 120 Hz，使用五次平滑时间曲线；普通到点等待为 80 ms。
  夹爪闭合、释放和视觉验收仍需短暂停顿。

## 本机测量

WSL2 / GUI 日志报告 llvmpipe 软件渲染。用下面的只读脚本采样 15 秒，
每次先预热 2 秒。数字为实际消息到达间隔，不是屏幕显示帧率保证。

```bash
python ~/ros2_ws/src/ros2_pybullet_arm/tools/render_timing_check.py
```

| 配置 | 关节状态 Hz | 状态间隔 P95 / 最大值 | 相机 Hz | 仿真/墙钟时间 |
| --- | --- | --- | --- | --- |
| 同线程渲染，448×448 / 5 Hz | 23.21 | 338.37 / 358.31 ms | 1.90 | 0.387 |
| 独立渲染，448×448 / 5 Hz | 59.20 | 18.91 / 35.49 ms | 3.05 | 0.987 |
| 双进程，320×320 / 15 Hz，分拣运行中 | 59.45 | 19.07 / 21.33 ms | 8.04 | 0.991 |

后两次测量没有出现超过 50 ms 的关节状态间隔。第一组与第二组用于观察
渲染隔离的改善，第三组是完整分拣默认配置；负载不同，不是严格性能基准。

15 Hz 是采样目标，不代表一定输出 15 fps。提高分辨率会降低相机实际帧率，
但图像渲染不再直接阻塞物理循环。相机预览仍受 CPU 和 WSL 图形性能影响。

## 调整

```bash
ros2 launch pybullet_arm_bringup sorting.launch.py
# 保留更高分辨率，代价是更低的相机帧率：
ros2 launch pybullet_arm_bringup sorting.launch.py camera_width:=448 camera_height:=448 camera_hz:=10.0
```

默认 320×320 已测试定位与物理分拣。任意降低分辨率可能使相邻同色物体
在图像中连成一个轮廓；改变相机配置后应重新验证识别和抓取。
